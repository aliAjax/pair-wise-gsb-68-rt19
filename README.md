# 新闻事实核查证据链与发布审阅工作台

基于React、Chakra UI、Zustand、React Router、TanStack Query、Axios、Vite和TypeScript的独立前端工程。数据使用浏览器本地持久化。

## 功能

- 核查主张列表、搜索、状态筛选和新建。
- 可验证事实树、支持证据、相反证据、置信度和未解决疑点。
- **共享来源库**：采访材料一处收入、多处复用；记录授权编号、授权方、范围与版本。
- **授权级联失效**：法务修改授权范围后，旧范围支持的事实立即变为「待重认」，相反证据与其他事实照常；已发布主张自动转入「停发复审」。
- **事实重认**：逐条按最新授权范围重新确认；已撤权来源未移除、旧稿来源未补编号时不允许重认。
- **撤权-发布撞车**：发布一侧始终按最新授权状态复审，未重认先停发，重认前停止导出当前档案。
- **发布快照锁定**：发布时刻完整快照（主张+来源+版本）入库，之后授权变更不改写历史档案；复审通过生成新快照，旧档案标记停发并原样保留。
- **旧稿迁移补录**：迁移来源授权编号为空时单独补录，补录不级联失效、不改写历史档案。
- **本机写入检查点**：批量补录先落检查点；中断后恢复只补未完成事实与审计，崩溃重放不重复记录。
- 原始证据、二次来源、待证信息分类与内容哈希留档，证据关系图、来源时间线、多人批注。
- 发布前校验、版本记录、完整档案与审计导出。

端口为`18468`。

```bash
npm install
npm run build
npm run dev
npm run test:rules   # 存储层授权/快照/检查点规则验证（43 项）
```

## 演示路径

1. 「共享来源库」对 `S-6 周明采访录音整理稿` 改授权范围或撤权：在核查中的 `FC-260928-03` 与已发布的 `FC-260927-02` 中，引用该采访的事实同时变为待重认，已发布主张转入停发复审。
2. 打开主张逐条「重新确认」，复核队列中「复审通过并重新发布」，到「档案与审计」对比新旧两份发布快照。
3. 对旧稿来源 `S-7` 补授权编号；历史档案不变。
4. 主张工作台「批量补录/检查点」模拟第 3 条写入失败，再用顶部检查点条恢复。
